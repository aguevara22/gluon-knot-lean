## Printed notions and their Lean renderings (all from the Chapter-3 layer, namespace `SM.Link`)

* "oriented links in S³" / "isotopy classes of oriented links": an oriented link is presented by a
  polygonal oriented link diagram `Diagram` (SM/LinkDiagram.lean: finitely many transverse double
  points, no triple points, an over strand at each), and its isotopy class is the `LinkEquiv`
  class — the equivalence relation generated by planar isotopy and the three Reidemeister moves
  (design decision D2, SM/LinkMoves.lean; Reidemeister's theorem is outside the formal scope).  "A
  map from isotopy classes" is therefore a map `Diagram → R` that descends to `LinkEquiv`
  (`∀ D D', LinkEquiv D D' → Q D = Q D'`).
* "P_L(a,z) ∈ ℤ[a^{±1},z^{±1}]": the map `SM.homfly : Diagram → R` fixed once by `Classical.choose`
  from `SM.lit_homfly`, with `R = ℤ[a^{±1}, z^{±1}]` (`SM.Link.R`, `R.a`, `R.aInv`, `R.z`).
* "P_○ = 1": value `1` on every one-component crossing-free diagram, `Diagram.IsCrossingFreeCircle`
  (design decision D10).
* "a P_{L₊} − a⁻¹ P_{L₋} = z P_{L₀} for every skein triple": `IsSkeinTriple D₊ D₋ D₀` (D₋ the switch of
  D₊ at a positive crossing, D₀ an oriented smoothing there; design decision D3).
* "In particular P_L is invariant under the Reidemeister moves": invariance under `RI`, `RII`,
  `RIII`; rendered, as the words "in particular" say, as a consequence of the descent clause (each
  move generates `LinkEquiv`: `LinkEquiv.of_RI/of_RII/of_RIII`).
* "P_K ∈ ℤ[a^{±1}, z²] for a knot K": `D.componentCount = 1 → InSupportM 1 (homfly D)`, where
  `InSupportM c f` is the library's `f ∈ M_c = z^{1−c} ℤ[a^{±1}, z²]` (lp:support,
  SM/LinkLaurentRing.lean); for `c = 1` this is literally `f ∈ ℤ[a^{±1}, z²]`: every monomial
  `a^d z^k` present in `f` has `k = 2j` with `j : ℕ` (`CV.inSupportM_one_iff`,
  `CV.ax_homfly_knot_parity_coeffAt` give the unfolded form).
* "so that the z^0 coefficient of a product of knot polynomials is the product of their z^0
  coefficients": the `[z^0]` row `zRow 0 : R → ℤ[a^{±1}]` (Mathlib's `LaurentPolynomial ℤ`) is
  multiplicative on `M_1`: `InSupportM 1 f → InSupportM 1 g → zRow 0 (f * g) = zRow 0 f * zRow 0 g`.
  This is stated for arbitrary `f g ∈ ℤ[a^{±1}, z²]` (the printed "knot polynomials" are the
  instances `f = homfly K`, `g = homfly K'` supplied by the parity clause), which is exactly the
  algebraic fact the printed sentence invokes and no more.
* "There is a unique map … satisfying P_○ = 1 and the skein": existence is `homfly` itself with the
  clauses above; uniqueness is the field `unique`: every `Q : Diagram → R` that descends to
  `LinkEquiv` classes, is `1` on the crossing-free circle and satisfies the skein equals `homfly`.
  Proved through lp:coefficient-transport (`SM.coefficient_transport`, whose competitor hypotheses
  `RCompetitor` — planar and RI/RII/RIII invariance — follow from `LinkEquiv`-descent since each
  generates `LinkEquiv`), NOT by assuming any R-uniqueness (the source struck that clause from
  lit:homfly; plan row 160 (2), Gap G9).
* The two clauses `rem:homflywhole` records as dropped (the disjoint-union value and the general
  multi-component z-order bound) are NOT stated: the entry as printed does not contain them.

## CV:ax:gausscode and the F4 replacement

Printed (d10_axioms.tex:525–531): "Let D and D′ be oriented link diagrams, each of whose underlying
plane curves is a connected generic immersed circle in the sphere — one component, transverse double
points, no triple points — and suppose there is an orientation-preserving record isomorphism from
the record of D to the record of D′ (Definition def:record).  Then D and D′ present the same
oriented link."

Fidelity decision F4 (work/reports/cv-lane-plan-20260913.md §2 F4 and row 163; OPEN_WORK.md):
CV:ax:gausscode is NOT assumed and is NOT proved as link equivalence.  "Present the same oriented
link" is outside the formal scope (it is Reidemeister's theorem plus Carter's classification; the
formal rendering `LinkEquiv` of "the oriented link presented by D" is generated by the moves, and no
sixth axiom is admitted), and every in-scope consumer of the entry (lem:pieceintrinsic,
prop:chamberinv(ii), lem:silence, cor:groupedknot(A)(B), lem:curl(i), and the R-assembly files
listed in F4) reads only the HOMFLY–PT polynomial of the two diagrams.  The row is therefore
replaced by its polynomial consequence

  `RecordIso D.record D'.record → homfly D = homfly D'`   for one-component diagrams,

which is SM rp:record-polynomial (`SM.record_polynomial.P_eq`, the source value and hence its
Gaussian evaluation `P` agree along a record isomorphism) composed with lp:core's identification
`P = homfly` (`SM.lp_core.eq_homfly`).  The checker keeps the row id `CV:ax:gausscode` pointed at
`CV.gausscode_polynomial`; the scope/checker change is to be recorded in work/AUTHOR_NOTES.md and
independently reviewed (row 163 (2)).

Renderings: "oriented link diagrams … transverse double points, no triple points": `Diagram` (these
two properties are part of the polygonal class itself, SM/LinkDiagram.lean); "one component /
connected … circle": `componentCount = 1`; "orientation-preserving record isomorphism from the
record of D to the record of D′": `RecordIso D.record D'.record` (SM/LinkRecord.lean: bijections
of circles and occurrences preserving `comp`, successor — i.e. the orientation of the traversal —
pairing, over/under bits and signs; `Diagram.record` is def:gauss-record, SM/LinkDiagramRecord.lean).
The one-component hypotheses `hD`, `hD'` are the printed domain and are kept in the statement
although the SM proof does not need them (rp:record-polynomial holds for any component count with
the component bijection); dropping them would make the Lean row strictly stronger than the printed
one, which is not this row's business. -/

/-! ## The `[z^0]`-row clause: `zRow 0` is multiplicative on `M_1 = ℤ[a^{±1}, z²]` -/

/-- `f ∈ M_1 = ℤ[a^{±1}, z²]` unfolded: every monomial `a^d z^k` present in `f` has `k = 2j`, `j : ℕ`
(even and nonnegative `z`-exponent).  The library's `InSupportM 1` reads `k = 1 − 1 + 2j`; this is the
wart-free form. -/
theorem inSupportM_one_iff (f : R) :
    InSupportM 1 f ↔ ∀ d k : ℤ, coeffAt d k f ≠ 0 → ∃ j : ℕ, k = 2 * (j : ℤ) := by
  rw [inSupportM_iff]
  constructor
  · intro h d k hk
    by_contra hne
    exact hk (h d k (by simpa using hne))
  · intro h d k hk
    by_contra hne
    obtain ⟨j, hj⟩ := h d k hne
    exact hk ⟨j, by simpa using hj⟩

/-- Every `z`-exponent in the support of an element of `M_1` is nonnegative. -/
theorem nonneg_snd_of_inSupportM_one {f : R} (hf : InSupportM 1 f) :
    ∀ e ∈ f.coeff.support, 0 ≤ e.2 := by
  intro e he
  obtain ⟨j, hj⟩ := hf e he
  rw [hj]
  push_cast
  omega

/-- The `[z^k]` row of `x` is the sum of the rows of its monomials (`zRow k` is additive). -/
theorem zRow_eq_sum (k : ℤ) (x : R) :
    zRow k x = x.coeff.sum fun e c => zRow k (AddMonoidAlgebra.single e c) := by
  conv_lhs => rw [← AddMonoidAlgebra.sum_coeff_single x]
  simp only [zRow]
  exact map_finsuppSum (zRowHom k) x.coeff AddMonoidAlgebra.single

/-- The `[z^k]` row of a product is the double sum of the rows of the products of monomials. -/
theorem zRow_mul_eq_sum (k : ℤ) (x y : R) :
    zRow k (x * y) = x.coeff.sum fun e c => y.coeff.sum fun e' c' =>
      zRow k (AddMonoidAlgebra.single e c * AddMonoidAlgebra.single e' c') := by
  conv_lhs => rw [← AddMonoidAlgebra.sum_coeff_single x, ← AddMonoidAlgebra.sum_coeff_single y]
  simp only [zRow]
  rw [Finsupp.sum_mul, map_finsuppSum]
  refine Finsupp.sum_congr fun e _ => ?_
  rw [Finsupp.mul_sum, map_finsuppSum]

/-- Monomial case: for `z`-exponents `k, k' ≥ 0`, the `[z^0]` row of `c a^p z^k · c' a^q z^{k'}` is the
product of the `[z^0]` rows (both sides vanish unless `k = k' = 0`). -/
theorem zRow_zero_single_mul_single (p q k k' c c' : ℤ) (hk : 0 ≤ k) (hk' : 0 ≤ k') :
    zRow 0 (AddMonoidAlgebra.single (p, k) c * AddMonoidAlgebra.single (q, k') c') =
      zRow 0 (AddMonoidAlgebra.single (p, k) c) * zRow 0 (AddMonoidAlgebra.single (q, k') c') := by
  rw [AddMonoidAlgebra.single_mul_single, Prod.mk_add_mk, zRow_single, zRow_single, zRow_single]
  -- `k + k' = 0 ↔ k = 0 ∧ k' = 0` for `k, k' ≥ 0`; the surviving case is `single_mul_single`
  split_ifs <;> first | omega | (rw [AddMonoidAlgebra.single_mul_single]) | simp

/-- "the z^0 coefficient of a product of knot polynomials is the product of their z^0 coefficients"
(ax:homfly, d10_axioms.tex:349–351), as the algebraic fact it invokes: on `M_1 = ℤ[a^{±1}, z²]` the
`[z^0]` row `zRow 0 : R → ℤ[a^{±1}]` is multiplicative.  Proof: expand both factors into monomials
(`sum_coeff_single`), use additivity of `zRow 0` and bilinearity of the product, and reduce to the
monomial case, where the nonnegativity of the `z`-exponents does the work. -/
theorem zRow_zero_mul_of_inSupportM_one {f g : R} (hf : InSupportM 1 f) (hg : InSupportM 1 g) :
    zRow 0 (f * g) = zRow 0 f * zRow 0 g := by
  rw [zRow_mul_eq_sum, zRow_eq_sum 0 f, zRow_eq_sum 0 g, Finsupp.sum_mul]
  refine Finsupp.sum_congr fun e he => ?_
  rw [Finsupp.mul_sum]
  refine Finsupp.sum_congr fun e' he' => ?_
  exact zRow_zero_single_mul_single e.1 e'.1 e.2 e'.2 _ _
    (nonneg_snd_of_inSupportM_one hf e he) (nonneg_snd_of_inSupportM_one hg e' he')

/-! ## The uniqueness clause: a `LinkEquiv`-descending competitor is an `RCompetitor` -/

/-- A map `Q : Diagram → R` that depends only on the isotopy class (`LinkEquiv`), is `1` on the
crossing-free circle and satisfies the skein is a competitor in the sense of lp:coefficient-transport
(`SM.RCompetitor`): planar isotopy and each Reidemeister move generate `LinkEquiv`. -/
theorem rcompetitor_of_descent (Q : Diagram → R)
    (hdesc : ∀ D D' : Diagram, LinkEquiv D D' → Q D = Q D')
    (hunknot : ∀ D : Diagram, D.IsCrossingFreeCircle → Q D = 1)
    (hskein : ∀ Dp Dm D0 : Diagram, IsSkeinTriple Dp Dm D0 →
      R.a * Q Dp - R.aInv * Q Dm = R.z * Q D0) :
    RCompetitor Q where
  planar D D' h := hdesc D D' (LinkEquiv.of_planarIsotopic h)
  reidemeister_I D D' h := hdesc D D' (LinkEquiv.of_RI h)
  reidemeister_II D D' h := hdesc D D' (LinkEquiv.of_RII h)
  reidemeister_III D D' h := hdesc D D' (LinkEquiv.of_RIII h)
  circle := hunknot
  skein := hskein

/-! ## Row 160 — CV:ax:homfly (d10_axioms.tex:342–360) -/

/-- The printed clauses of CV:ax:homfly (d10_axioms.tex:342–351), one field per clause, for the
HOMFLY–PT polynomial `homfly : Diagram → R` of lit:homfly.  See the module docstring for every

structure AxHomflyData : Prop where
  /-- "a … map L ↦ P_L(a,z) … from isotopy classes of oriented links in S³": `homfly` descends to
  `LinkEquiv` classes. -/
  descent : ∀ D D' : Diagram, LinkEquiv D D' → homfly D = homfly D'
  /-- "P_○ = 1": value `1` on every one-component crossing-free diagram. -/
  unknot : ∀ D : Diagram, D.IsCrossingFreeCircle → homfly D = 1
  /-- "a P_{L₊} − a⁻¹ P_{L₋} = z P_{L₀} for every skein triple". -/
  skein : ∀ Dp Dm D0 : Diagram, IsSkeinTriple Dp Dm D0 →
    R.a * homfly Dp - R.aInv * homfly Dm = R.z * homfly D0
  /-- "In particular P_L is invariant under the Reidemeister moves": moves I, II, III. -/
  reidemeister :
    (∀ D D' : Diagram, RI D D' → homfly D = homfly D') ∧
    (∀ D D' : Diagram, RII D D' → homfly D = homfly D') ∧
    (∀ D D' : Diagram, RIII D D' → homfly D = homfly D')
  /-- "P_K ∈ ℤ[a^{±1}, z²] for a knot K": on a one-component diagram, `homfly D ∈ M_1 = ℤ[a^{±1}, z²]`
  (every monomial `a^d z^k` present has `k = 2j`, `j : ℕ`; `CV.inSupportM_one_iff`). -/
  knot_parity : ∀ D : Diagram, D.componentCount = 1 → InSupportM 1 (homfly D)
  /-- "so that the z^0 coefficient of a product of knot polynomials is the product of their z^0
  coefficients": `zRow 0` is multiplicative on `ℤ[a^{±1}, z²]`. -/
  knot_product_z0 : ∀ f g : R, InSupportM 1 f → InSupportM 1 g →
    zRow 0 (f * g) = zRow 0 f * zRow 0 g
  /-- "There is a unique map … satisfying P_○ = 1 and [the skein]": any map from isotopy classes
  (a `LinkEquiv`-descending `Q : Diagram → R`) with `Q_○ = 1` and the skein equals `homfly`. -/
  unique : ∀ Q : Diagram → R,
    (∀ D D' : Diagram, LinkEquiv D D' → Q D = Q D') →
    (∀ D : Diagram, D.IsCrossingFreeCircle → Q D = 1) →
    (∀ Dp Dm D0 : Diagram, IsSkeinTriple Dp Dm D0 →
      R.a * Q Dp - R.aInv * Q Dm = R.z * Q D0) →
    Q = homfly
